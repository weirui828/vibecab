# Decisions

Choices not dictated by the design, newest last. Format: date — decision — reason — who.

## Pre-seeded (Wei, 2026-10-28)

- 2026-10-28 — Engine language: TypeScript on Node.js 26 LTS. — Mature model-provider and MCP SDKs; strongest coding-agent fluency; shares contract types with a future TypeScript UI. — Wei
- 2026-10-28 — Build the local, single-person engine first (SQLite, single writer); cloud later behind the same contract. — Fastest path to a working covibe loop. — Wei
- 2026-10-28 — Model gateway is VibeCab's own provider-neutral interface; the first provider adapter targets the OpenAI-compatible Chat Completions API with configurable base URL and model. — De facto standard covered by many providers; native adapters can be added later without engine changes. — Wei
- 2026-10-28 — First media kind is `doc` (engine name; the user-facing name is decided later): block tree per AGENTS.md §9, inline-Markdown subset inside text. — Supports structured text well with stable, LLM-friendly ids. — Wei
- 2026-10-28 — Current scope: core engine, contract and adapters only; no UI, no product-journey fixtures. LLM-dependent behaviour is tested with a scripted fake provider. — Wei

## Pre-seeded design refinements (Claude, 2026-10-28)

- 2026-10-28 — Commit staleness is checked per element in the write set (hash at head = hash at base); a parent only has to exist at head and allow the child type, its own hash may differ. — The parent's hash doesn't include its children, so editing a parent's text never conflicts with adding a child. Refines design §5.3 "and its parent". — Claude
- 2026-10-28 — L1 stores the full manifest per version (`vc_version_entries`); delta storage is a later optimization. — Simplicity first; documents have hundreds of blocks, not millions. — Claude
- 2026-10-28 — Sibling order uses engine-generated fractional indexes; callers pass `after` (an element id or null). — Callers never compute order strings, so concurrent inserts can't collide. — Claude

- 2026-10-28 — Use mdast-util-from-markdown with GFM extensions for Markdown parsing. — Established CommonMark parser with typed syntax trees and explicit GFM table support; parsing is local with no URL fetches. — Codex
- 2026-10-28 — Use Node's built-in HTTP server and a permission-restricted workspace token file for L1. — Avoids a transport framework dependency; keychain-backed tokens remain out of scope. — Codex
- 2026-10-28 — Use ajv-formats for RFC 3339 timestamps and URI formats. — AJV's standard maintained format implementation avoids reimplementing boundary validation. — Codex

- 2026-10-28 — Import into an existing artifact appends blocks; restore reuses historical IDs, order strings and revisions via an internal mode of the shared commit function. — Explicitly confirmed by Wei; preserves anchor identity and exact restore manifests. — Wei / Codex
- 2026-10-29 — Pin Node 26.13.0 and matching Node 26 types in the workspace. — Wei requested upgrading the project runtime to Node 26; 26.13.0 is the latest LTS release. — Codex

- 2026-10-28 — The in-process adapter defaults to admin and permits trusted-host scope narrowing. — Explicitly confirmed by Wei so all adapters can exercise the same authorization contract tests. — Wei / Codex
- 2026-10-28 — HTTP errors map to standard statuses (400 invalid, 401 unauthenticated, 403 forbidden, 404 not_found, 409 conflict/stale_base, 423 locked, 402 budget_exceeded, 429 rate_limited, 501 unsupported, 503 unavailable/uncertain, 500 internal); request bodies are capped at 16 MiB. — Design defines error names but omits numeric statuses; bounded bodies protect the local listener. — Codex

- 2026-10-28 — A new-artifact import creates its populated version 1; omitted `after` appends and explicit null prepends. — Avoids an empty initial version and preserves incoming block order. — Codex
- 2026-10-28 — Production HTTP tokens use cryptographic randomness; tests inject deterministic token factories. — Authentication secrets must not derive from the engine test seed. — Codex

- 2026-10-28 — Persist validated, authorized command failures with a nested savepoint so retries return the same result while mutations roll back. — Extends idempotency to failed domain commands without caching authorization failures. — Codex
- 2026-10-28 — Use outbox attempt numbers as lease fences, retry only known local idempotent kinds, and suppress late completions after drain. — A stale handler must not complete a later attempt or write after storage closes. — Codex

- 2026-10-28 — Keep internal workspace exports at TypeScript sources and emit a complete JavaScript workspace with `pnpm build`. — Preserves relative module boundaries without adding a bundler; runtime schemas are copied alongside the emitted contract. — Codex
- 2026-10-28 — Property checks yield between runs. — Thousands of synchronous AJV/SQLite fixtures starved Vitest worker RPC despite passing assertions; yielding preserves all checks and keeps the runner responsive. — Codex

- 2026-10-28 — Upgrade direct dependencies to current stable releases, including TypeScript 7, Vitest 5, ESLint 10 and pnpm 12; use the latest Node 26 LTS runtime and matching Node 26 types. — Wei requested most recent libraries and then explicitly upgraded the runtime to Node 26. — Codex
- 2026-10-28 — Isolate the latest typescript-eslint in a private tools/lint workspace with TypeScript 6.0.3 and disable workspace-root peer resolution. — Its published peer range is <6.1 and the TypeScript 7 compiler no longer exposes the legacy compiler API; engine builds/typechecks still use TypeScript 7.0.2. — Codex
- 2026-10-28 — Remove @types/diff. — Current diff ships its own declarations and the latest @types/diff is a deprecated stub. — Codex

- 2026-10-28 — Set pnpm minimumReleaseAge to zero for this workspace. — pnpm 12 defaults to delaying fresh releases, which blocked packages already in the old lockfile and contradicts the explicit request to use the latest stable releases. — Codex

- 2026-10-28 — Declare current Vite 8 explicitly and refresh transitive dependencies within their declared ranges. — Vitest 5 accepts Vite 8 but retained Vite 7 from the old lockfile; the upgrade should use the latest supported test transformer as well. — Codex

- 2026-10-28 — Map canonicalize 5 serialization failures to ContractError invalid. — Its stricter Unicode validation rejects unpaired surrogates; callers must receive an input error rather than an internal engine failure. Existing valid canonical bytes and hashes are covered by compatibility tests. — Codex
- 2026-10-29 — Store Task 02 domain records in a kind/id keyed `vc_feedback` table behind repository methods. — Ideas, projects, sessions, threads, agreements, and conflicts share command transactions and JSON Schema validation without coupling their modules to SQLite. — Codex
- 2026-10-29 — Use the official `openai` SDK for the OpenAI-compatible Chat Completions adapter and `@napi-rs/keyring` for OS keychain storage. — The gateway design requires the supported upstream SDK and a native credential store; adapters keep SDK types isolated and settings persist references only. — Codex
- 2026-10-29 — Estimate input tokens with `ceil(total message characters / 3)` and round each priced token component up to integer micro-units. — This deliberately overestimates small requests and keeps reservation arithmetic deterministic. — Codex
- 2026-10-29 — Persist Task 04 agent turns, context manifests, grants, and delivery state through the repository's kind/id feedback records; version reply prompts as checked-in Markdown. — Reuses the validated single-writer persistence layer and makes the exact prompt hash inspectable. — Codex
- 2026-10-29 — Use SQLite FTS5 for session scoped comment and attached artifact search; index current artifact text and exclude soft deleted comments. — Keeps search local and ensures agent retrieval respects session attachment boundaries. — Codex
- 2026-10-29 — When restore undoes an Update, retain the applied agreement and record `revertedInVersion` with a system notice. — Preserves the history of human agreement and makes the restore visible in its originating thread. — Wei's Task 05 requirement / Codex implementation
- 2026-10-29 — Run Updates as outbox jobs; persist planner output before a session plan-review gate and recheck staleness per changed element at commit. — Model calls stay outside command transactions, and unrelated direct edits can still land while a planner or writer is running. — Codex
- 2026-10-29 — A planner or writer failure leaves affected agreements agreed and commits no version; valid non-stale write-set elements can still commit when other planned elements became stale. — Preserves item accounting and the per-element commit invariant across interruptions and direct edits. — Codex
- 2026-10-29 — Update records capture the human agreer per item, and Update versions use the Update's writer-turn id as `createdBy`. — Adds provenance while keeping restore/import system authorship distinct; the `update` JSON Schema adds optional-on-input but engine-populated `onBehalfOf` data for backward-compatible stored records. — Codex
- 2026-10-29 — Expose an optional injected Update checkpoint after writer validation and before commit. — Gives shutdown recovery tests a deterministic way to stop at the checking boundary without changing production defaults. — Codex
- 2026-10-29 — Implement backup restore as `Engine.restoreBackup(archivePath, destinationDir)`, available only while stopped; validate a temporary extraction and its manifest hashes before placing it in an empty destination. — Restore is an engine lifecycle operation because a contract command cannot run against a stopped workspace; rejecting links and special archive members prevents extraction outside the validated staging tree. — Wei / Codex
- 2026-10-29 — Use the platform `tar` executable for Task 06 archive creation and extraction. — The archive format is tar.gz and this local build targets Node 26 on developer workstations; keeping archive I/O outside the runtime dependency graph avoids a second archive implementation. — Codex
- 2026-10-29 — Resolve adapter credentials in the engine for every contract call; use a workspace SQLite HMAC key for channel-bound 256-bit tokens, constant-time comparisons, immediate revocation checks, and a per-transport failed-attempt limiter. — Adapters must not choose `CallContext.channel` or `scope`; storing the HMAC key in SQLite keeps token verification intact across backup restore. One-time token command results are replaced with an `uncertain` idempotency record so the secret is never persisted. — Wei / Codex
- 2026-10-29 — Map CLI errors to stable exit codes: invalid 2, unauthenticated 3, forbidden 4, not_found 5, conflict/stale_base/locked 6, budget_exceeded/rate_limited 7, unsupported 8, unavailable/uncertain 9, internal 10. — Shell scripts can distinguish contract failures without parsing messages. — Codex
- 2026-10-29 — Build Task 08 on the current official MCP TypeScript SDK v2 packages (`@modelcontextprotocol/server` and its client for tests), with Zod's JSON Schema bridge and loopback Streamable HTTP. — The SDK accepts Standard Schema inputs and validates tool outputs as structured objects, so results are exposed as `{ result }` envelopes while preserving each operation's result schema inside the envelope. `sys.Capabilities` includes the engine-resolved call channel and scope so tool visibility never depends on adapter-selected authority. Comments retain their engine-derived transport channel for attribution. — Codex
- 2026-10-29 — The local engine stays single-process, single-workspace, single-person: synchronous Repository, no workspace/user ids, in-process timers and queues are acceptable. No cloud-portability refactor now; a cloud build will be a separate effort that reuses the contract, domain rules and tests but ports storage, kernel and access. Do not add cloud abstractions speculatively. — Wei

- 2026-10-29 — MCP assistants can comment, agree and trigger Updates, but cannot edit content directly; importing into an existing artifact is also blocked on MCP. — Keeps content changes inside the comment → agree → Update path and its write-set checks. — Wei

- 2026-10-29 — MCP tool-server commands persist configuration synchronously and enqueue an async discovery job; they return `connecting` until discovery updates the record. — The command kernel is transactional and synchronous, so network I/O stays outside command transactions and is recoverable as a job. — Codex
- 2026-10-29 — External MCP tool results are untrusted, size-limited context; the engine enforces per-tool policy, exact tool grants, session/project scope, and a per-turn call budget. Audit records retain hashes, sizes and outcomes without args/results or credentials. — Keeps external server content from authorizing changes and preserves a content-free audit trail. — Codex

## macOS app (Wei, 2026-10-29)

- 2026-10-30 — Use Electron 45.1.0, the current stable release used for A1, and `@electron/fuses` 2.1.3 with RunAsNode, Node options, and Node inspector fuses disabled. — The app keeps engine work in a separately launched Node 26 process and closes Electron's Node execution paths. — Task A1 / Codex
- 2026-10-30 — Move workspace ownership to `@vibecab/host`; app, CLI and MCP use one process, and MCP stdio is a credential-forwarding relay. — Avoids workspace-lock contention and gives the desktop app a stable local engine endpoint. — Task A0 / Codex
- 2026-10-30 — Artifact `updatedAt` follows the latest version commit or metadata rename; session attachment ids are returned in attachment order. — Lets app lists sort by recent activity and refresh session relationships without polling or extra queries. — Task A0 / Codex
- 2026-10-30 — The MCP stdio relay forwards host tool results without revalidating downstream output schemas; the host validates them, and the relay SDK cannot compile schemas with external contract references. — Prevents a relay-only failure while keeping the host as the validation authority. — Task A1b / Codex
- 2026-10-30 — Tests may set `VIBECAB_HOST_ENTRY` only with `VIBECAB_DEV=1` to exercise stopped-host relay startup without keychain dependencies. — Keeps the production host entry fixed while making lifecycle tests hermetic. — Task A1b / Codex
- 2026-10-30 — Use Testing Library with jsdom for the renderer’s live-host integration test. — Exercises the actual Home component through the same ContractBridge shape without requiring Electron in unit tests. — Task A1b / Codex

- 2026-10-29 — Desktop app shell: Electron, with the engine as a separate Node 26 process shared with the CLI and MCP relay through `@vibecab/host`; the app talks to it over the HTTP adapter and SSE via a main-process bridge. — One TypeScript stack; Electron's own Node never loads the engine's native modules. — Wei
- 2026-10-29 — Closing the window keeps the engine running in the menu bar; Quit stops it after draining. — Agent replies and Updates keep working while the window is closed. — Wei
- 2026-10-29 — Look: Tundra theme from `@wei/design-system` (light and dark), vendored as a packed tarball. — Wei's own design system; the private repo has no published build. — Wei
- 2026-10-29 — Distribution: personal, unsigned (ad-hoc signed), Apple Silicon only, macOS 14+. Mac App Store possibly later; keep paths in one module and don't preclude sandboxing. — Wei
- 2026-10-29 — User-facing names: **Draft** (any artifact, all media kinds), **Document** (the `doc` media kind), **Snapshot** (Output Set). Engine, contract, CLI, MCP and API keep `artifact`, `doc`, `OutputSet`; renaming is a UI-only change in `apps/ui/src/copy/terms.ts`. — Display names may change; integrations must not break when they do. — Wei
- 2026-10-29 — App defaults: name "VibeCab"; workspace `~/Library/Application Support/VibeCab/workspaces/default`; the app reuses a running engine host; code in `apps/ui` (renderer) and `apps/macos` (Electron). — Proposed by Claude, approved by Wei with the task specs. — Wei
- 2026-10-29 — App icon and branding come from the VC cab mark and wordmarks in `weirui828/vibecab-0`; the 1024 px icon needs Wei's original artwork. — Wei
- 2026-10-29 — Update turns use only `allowed` read-only external tools, never `needs_grant` tools, even when a grant names them. — Updates have a bounded write set and external tools provide context only; allowing mutating tools would add effects outside that write set. — Codex
- 2026-10-29 — TMR stores immutable input snapshots and frozen process specs in repository feedback records, and shares the kernel's RFC 8785 canonicalizer without importing VibeCab domain modules. — Keeps TMR independently usable while reusing the single-writer store and consistent payload hashing. — Codex
- 2026-10-29 — Ship the independent-review preset with isolated snapshot assessments followed by synthesis, and mark demo output in every run, contribution, and report. — Provides one inspectable default while keeping demo results clearly distinct from live model output. — Codex
- 2026-10-29 — Encode TMR source references as `vc:artifact/<artifactId>@<version>#<elementId>` for elements and `vc:comment/<commentId>` for comments; other sources stay opaque. `PurgeBySource` matches exact sources or the next `@`, `#` or `/` boundary. — Artifact-level purge must cover every version without matching similarly prefixed artifact ids. TMR records remain in the generic feedback store; index by runId if runs exceed a few thousand. `Participant.systemPromptHash` is the caller-declared participant prompt configuration digest; run-level hashes cover the frozen engine prompt templates stored with each run, where `roleLabel` is the only substituted variable. — Task 10b / Codex
- 2026-10-29 — TMR recovery writes an `interrupted` report first, then invokes the shared `tmr.Resume` handler only when the frozen run has `limits.autoResume: true`; otherwise the run waits for an explicit Resume command. — The interrupted report preserves recovery evidence, while configured auto-resume uses the same transition and dispatch checks as a manual resume. — Task 10b follow-up / Wei
- 2026-10-30 — VibeCab review conversion takes the final human-approved fields, including a required `mode`; agents only draft, and `RequestReview`/`ConvertSuggestedReview` accept human principals. Integration calls Feedback, Updates, and TMR only through injected typed ports. Purging dependent reviews requires an explicit redact/delete choice per run and delegates through an integration lifecycle hook. — Keeps submission human-authorized, prevents silent demo fallback, and keeps domain record ownership inside each module. — Wei / Task 11
- 2026-10-30 — Integration poll jobs put their due time in the job payload's `notBefore` field and use a time-qualified idempotency key. — JobRunner reads `notBefore` from payload; storing the timestamp only as the enqueue creation time caused a completed report to remain undelivered. — Codex / Task 11
